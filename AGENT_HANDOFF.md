## PHASE 1: 15 SCOPING QUESTIONS (Answered)

### Q1: What are we building?
**ANSWER:** A nonprofit youth tech community platform with ORCID-style credential verification (Trust Markers), hackathon management (Devpost/MLH clone), and regional chapter system for Nepal. Phase 1 scope: Landing page + Hacker profiles + Dashboard stubs.

### Q2: Who are the users?
**ANSWER:** Three RBAC roles:
- 🟢 **Hackers** (Builders) — Claim BH-ID, earn Trust Markers, submit projects
- 🟡 **Organizers** (Issuers) — Create events, issue markers, manage check-ins
- 🔴 **Maintainers** (Core Team) — God mode, revoke markers, audit log

### Q3: What's the MVP scope for Phase 1?
**ANSWER:**
- ✅ Landing page (Hero, Programs, Metrics, Values, FAQ)
- ✅ Hacker profile page (`/p/[slug_id]`) with Trust Markers
- ✅ Dashboard stubs (Hacker, Organizer, Maintainer)
- ✅ API endpoints (metrics, contact)
- ✅ Dark mode + accessibility pass
- ❌ NO AI features (deferred to Phase 2)
- ❌ NO real-time chat (deferred to Phase 2)
- ❌ NO Open Collective bounties (deferred to Phase 2)

### Q4: What's the design system?
**ANSWER:** Liquid Glass aesthetic:
- Dark mode base: `#242424` (Temple Black)
- Glass surface: `#434343` at 70% opacity with `backdrop-blur-[30px]`
- Primary red: `#FE0000` (Heritage Red) for CTAs and Trust Markers
- Typography: Inter (headings), JetBrains Mono (technical data)
- Concentric math: Inner Radius = Outer Radius - Padding

### Q5: Is there a Figma file?
**ANSWER:** No. The design system is auto-generated by UI UX Pro Max and stored in `design-system/MASTER.md`. All components must reference these tokens.

### Q6: What about responsive design?
**ANSWER:**
- Mobile-first approach
- Breakpoints: `sm:640px`, `md:768px`, `lg:1024px`, `xl:1280px`
- Bento Grid: 1 col (mobile) → 2 cols (tablet) → 3 cols (desktop)
- Navbar: Hamburger menu on mobile, full nav on desktop
- Touch targets: Minimum 44x44px

### Q7: What database are we using?
**ANSWER:** Supabase (PostgreSQL) with:
- Service Role Key ONLY (bypasses RLS)
- NO Supabase Auth (Auth0 handles auth)
- Tables: `profiles`, `events`, `trust_markers`, `projects`, `teams`, `audit_logs`
- `auth0_user_id` column links Auth0 identity to Supabase profile

### Q8: What's the existing schema?
**ANSWER:** Schema exists in `supabase/migrations/`:
- `001_initial_schema.sql` — Core tables
- `002_auth_trigger.sql` — Ghost Profile merge logic
- `010_auth0_migration.sql` — Added `auth0_user_id` column

### Q9: Can we use seed data?
**ANSWER:** Yes. Create seed data for:
- 3 hackers (BH-24-001, BH-24-002, BH-24-003)
- 1 organizer
- 1 maintainer
- 2 events (1 upcoming, 1 past)
- 3 trust markers (1 verified, 1 self-reported, 1 revoked)
- 2 projects

### Q10: What features are in Phase 1?
**ANSWER:**
- ✅ Auth0 login (GitHub, Google, Email)
- ✅ Public landing page
- ✅ Public hacker profiles (`/p/[slug_id]`)
- ✅ Dashboard stubs (view-only, no interactivity)
- ✅ Contact form (sends email via Resend)
- ✅ Dark mode toggle
- ✅ PWA manifest

### Q11: What about email?
**ANSWER:** Resend API for:
- Contact form submissions
- Ghost Profile claim notifications
- NO email verification flow (Auth0 handles that)

### Q12: What analytics are tracked?
**ANSWER:**
- Vercel Analytics (traffic, page views)
- PostHog (funnel tracking: Sign-up → Profile Complete → Project Submit)
- NO Sentry in Phase 1 (defer to Phase 2)

### Q13: What env vars are required?
**ANSWER:**
```env
# Core
NEXT_PUBLIC_SITE_URL=http://localhost:3000
NEXT_PUBLIC_APP_URL=http://app.localhost:3000

# Auth0

# Supabase

NEXT_PUBLIC_SUPABASE_ANON_KEY=your_anon_key
SUPABASE_SERVICE_ROLE_KEY=your_service_role_key

# Cloudinary
CLOUDINARY_CLOUD_NAME=your_cloud_name
CLOUDINARY_API_KEY=your_api_key
CLOUDINARY_API_SECRET=your_api_secret

# Upstash (Rate Limiting)
UPSTASH_REDIS_REST_URL=your_upstash_url
UPSTASH_REDIS_REST_TOKEN=your_upstash_token

# Resend
RESEND_API_KEY=your_resend_api_key
```

3. Ensure ALL colors use Tailwind arbitrary values (NO inline styles)
4. Ensure ALL images use `next/image` with `fill` and `object-cover`
5. Add `export const dynamic = 'force-static'` for CDN caching

**Success Criteria:**

### Step 5: Create API Endpoints (20 min)
**Tasks:**
1. Build `/api/metrics/route.ts`:
   - GET: Return public stats (total hackers, events, projects)
   - Rate limited: 30 requests per minute
   - No auth required

2. Build `/api/contact/route.ts`:
   - POST: Accept name, email, message
   - Zod validation
   - Rate limited: 5 requests per minute
   - Send email via Resend
   - No auth required

3. Build `/api/webhooks/auth0/route.ts`:
   - POST: Receive Auth0 user events
   - Verify webhook signature
   - Sync user to Supabase `profiles` table
   - Generate BH-ID if new user

**Success Criteria:**
- ✅ `/api/metrics` returns JSON
- ✅ `/api/contact` sends email
- ✅ `/api/webhooks/auth0` syncs user to Supabase
